# 桌面音乐与视频播放器

顶部常驻的迷你播放器 + 一个悬浮面板 + 一个可拖拽的视频窗。曲库在本地，音频和视频共用一套索引、歌单与检索逻辑。下载走 B 站 DASH 流，转码/合流用这台机器上唧唧DOWN 自带的 `ffmpeg.exe`。全程后台，不弹唧唧的窗口。

## 在哪里

- **顶栏入口**：会话标题左侧那颗小胶囊（`conversation.header.leading`）。有内容时显示「标题 · UP 主」；视频前面挂一个**胶卷图标**，音频不挂。
  - 胶囊最左侧是播放状态标记：暂停时是 ▶ 三角，播放时是 ⏸ 双杠，切换带一小段缩放动画，播放中双杠还会轻微呼吸。
  - 点一下展开面板，胶囊右边还有 ⏮ ⏯ ⏭ 三个按钮。
- **面板**：悬浮卡片，五个页签 —— 曲库 / 搜索 / 点歌 / 外观 / 按键。
  - **可以自己挪**：按住标题区拖动，右下角小三角拖动改大小，位置尺寸记在 `localStorage`（`dsh-music-panel-rect`），刷新/重启都还在；「外观 → 面板 → 复位」回到默认右上角。
- **视频窗**：独立浮层（`shell.overlay`），同样可拖可缩，带 播放/暂停、进度、音量、全屏、PiP、置顶。

## 曲库（音频 + 视频）

- **类型筛选**：全部 / 音频 / 视频。**视频行左侧是胶卷图标**，音频行是 `♪`，一眼分得开。
- **歌单**：顶部条是「全部 / 收藏 / 各歌单 / ＋歌单」。选中歌单后可改名、删除（两步确认）。
  - 每行右侧 `＋` 把整个面板切成**歌单目录**：列出所有歌单并带上勾选状态，点一行就是加入/移出，勾着的就是这首已经在的歌单；底部可以直接新建并顺手加进去。
  - 行下面会列出这首歌已在哪几个歌单（`#歌单名`）。
- **批量**：点「多选」进入勾选模式，批量条支持「加入歌单 / 收藏 / 移除 / 删文件 / 取消」；「加入歌单」同样进入歌单目录，一次给多首勾。
- **新建歌单的输入条**：点到面板别处（切页签、点行、点歌单条）会自动收起，不会一直挂着。
- **排序**：最近添加、标题、UP 主、时长、播放次数，升降序切换。
- **筛选**：本地关键词过滤（标题/UP 主/标签/分类）。

## 搜索（B 站）

- 关键词回车 → 宿主进程检索（先取 `buvid3` cookie，被 412 风控会自动换一次），面板不跨域。
- 下拉选「下音频」或「下视频」：音频转 mp3，视频下 DASH 视频流（优先 avc1）+ 音轨后用 `-c copy` 合并成 mp4。
- 若当前选中了某个歌单，下完的东西会自动进那个歌单。
- 进度条显示下载阶段（取流 / 下载 / 转码或合并）。

## 点歌（一次性代理，不带历史）

输入框不发搜索请求，而是**起一个一次性子代理**：面板拿当前会话 id，宿主调
`ctx.subagents.startActivation({ provider: 'spawn', ... })`，子代理用的是专用预设
`music`（曲库助手），跑完一轮就把结果回给面板。

这么做的原因：早先是把话 `followup` 回当前会话，会话里攒了多少历史，模型就得读多少——
聊上几轮就是几十万 token，旧会话那次 422 就是这么塌的。现在每次点歌都是干净上下文：

| 项目 | 值 |
| --- | --- |
| 预设 | `music`（`@local/dsh-music-agent-preset`） |
| 系统提示词 | 350 字左右的曲库规则（`complete` 模式，不带人格/记忆） |
| 工具 | 只有 `music_*` 六个（预设里的 `restrict-music-tools` 把其余全局工具收窄掉） |
| 模型 | `deepseek-flash`，思考档位默认 `low`（要更省改 `off`，要更绕改 `high`） |
| 会话 | `origin: subagent`，挂在当前对话的树下面，当记录 |

实测：一次「播播放次数最多的」= 请求头 5.1 KB、3 秒回话。

三种模式：

| 模式 | 干什么 |
| --- | --- |
| 找新歌 | `music_search` 检索 → `music_download` 入库（可带 tags / category / 歌单） |
| 整理曲库 | `music_library` 看现状 → `music_playlist` 建歌单归类，不下载 |
| 播给我听 | 从曲库挑 → `music_player` 直接放 |

「深度思考」开关会把「先分步推理（搜什么词、挑哪几首、怎么分类）再动手」写进请求；关掉就是直接执行。模式与开关都记在设置里。

想退回旧行为（把话递回当前会话）就把 `settings.json` 里的 `askFresh` 设成 `false`；
`askPreset` / `askProvider` / `askModel` / `askEffort` / `askTimeoutMs` 可以逐个改。

模型侧工具：

| 工具 | 作用 |
| --- | --- |
| `music_search` | B 站检索，返回 BV 号 / 标题 / UP 主 / 时长 / 封面 |
| `music_download` | 按 BV 号下载，`kind: audio\|video`，可带 tags / category / playlistId |
| `music_playlist` | list / create / add / remove / rename / delete / detail / of |
| `music_library` | list（可按 kind 筛）/ update / remove / scan / stats / migrate |
| `music_player` | status / play / pause / next / prev / volume / seek / repeat / shuffle / play_track / play_bvid / video_window / open / close |
| `music_skin` | get / apply / reset —— 按描述配色并写进皮肤 |

## 进度条与媒体加载

- 面板和视频窗的进度条都改成按 `step` 细分的真实时长拖动，短片子也不糊。
- 媒体源走**本地 blob**（≤80MB）：整段读进内存再交给 `<audio>/<video>`，`seekable` 直接等于全长，拖到哪儿就是哪儿。超过 80MB 的退回流式 HTTP。
- 音频/视频元素始终挂在文档里的隐藏容器，不会被摘掉——被摘掉的媒体元素在 Chromium 里 `seekable` 会塌成 `[0,0]`，那才是"一拖就回到开头"的元凶。
- 元数据没到时拖进度条会把目标时间记下来，等 `loadedmetadata` 再跳，不吃掉这次拖动。
- 拖到最右端会停在结尾前 0.12 秒，避免短片子一拖就触发 `ended` 然后看起来像重播。
- 时长不到 10 秒的媒体时间显示带一位小数（`0:04.3 / 0:04.3`），不会出现 `0:00 / 0:00`。

## 视频窗口

- 播视频时按设置自动打开（「外观 → 视频窗 → 播视频自动开」），也可以点传送条上的视频按钮或快捷键手动开关。
- **从视频切到音频时，视频窗自动收起**（不是挂着显示"音频没有画面"），音频照常在后台放。
- 窗口里自带一套完整控制：**进度条**（可拖）、时间、**上一首 / 播放暂停 / 下一首**、**音量**（可点图标静音）、画中画、全屏、关闭。
- 拖标题栏移动、拖右下角缩放，位置和尺寸记在 `localStorage`，下次照样。
- **真全屏**：点「全屏」或按快捷键（默认全局 `Ctrl+Shift+F`，面板内 `F`）走浏览器的 Fullscreen API —— 整个窗口（包括 DSH 的标题栏、侧栏、右上角关闭/最小化/分页）都会让出来，只剩画面。`Esc` 或再按一次退出。
- **全屏下控件自动隐藏**：鼠标静默 2.6 秒、且正在播放时，进度条/切歌/音量/标题栏会淡出；动一下鼠标（或按键）立刻回来。暂停时不会藏，免得找不到按钮。退出全屏后控件常驻。
- 音频曲目在全屏窗里给提示而不是黑屏；关掉窗口不会停止播放，重新打开会重新挂上画面。

## 皮肤与自定义外观

- 六套预设（深海鲸蓝 / 午夜黑 / 樱花粉 / 赛博霓虹 / 松林绿 / 纸白）+ 主色、底色、模糊、不透明度、圆角、氛围光、动画逐项可调。
- **导入自己的图**：外观页「导入背景图」选 png/jpeg/webp，浏览器先缩到 1600px 再交给宿主，图片存在 `%USERPROFILE%\.dsh\music-player\skin\`；「压暗」滑块决定图上文字清不清楚，「移除」删掉。
- **自定渐变**：填一条 `linear-gradient(...)` / `radial-gradient(...)` 直接当背景。
- **让模型设计**：填一句「赛博霓虹 / 深海寂静 / 宣纸墨色」，点「让模型设计」——请求递回当前会话，模型先讲设计思路，再调 `music_skin` 把 accent / surface / text / gradient / 模糊 / 圆角写进皮肤，面板下一拍就换。已导入的图片不会被配色覆盖（有图时图片优先，没图才用渐变）。
- 模型侧只收窄口子：颜色限 `#RRGGBB` / `rgb()` / `hsl()`，渐变限 `linear-gradient` / `radial-gradient`，数值夹到合理区间，写不出能砸坏界面的值。

## 存储位置

- 默认落在 `E:\DshMusic`（没有 E 盘时退回 `~\Music\DshMusic`）。
- 外观页「存储位置」可以一键「迁到 E:\DshMusic」，或填任意目录迁过去：文件先复制再删源（跨盘 `rename` 会失败），索引路径、下载目录一起同步；同名文件跳过并在提示里报数量。
- 模型也能做这件事：`music_library` action=`migrate`, `to="E:\DshMusic"`。

## 快捷键（可自定义）

「按键」页两栏，点右侧按键按钮后直接按想绑的键即可；「清」解绑，「恢复默认」回滚。

- **全局**（页面任意处，输入框里不触发）：播放/暂停、上/下一首、音量 ±、静音、面板开关、视频窗开关、视频窗全屏
- **面板内**（面板打开时）：播放/暂停、快进/快退 5 秒、音量 ±、静音、收起、视频窗全屏

默认值：全局 `Ctrl+Shift+Space / ←→ / ↑↓ / M / P / V / F`，面板内 `空格 / ←→ / ↑↓ / M / Esc / F`。系统媒体键（播放/暂停、上一首、下一首、快进快退 10 秒）走 `navigator.mediaSession`，耳机线控也能用；全屏时 `Esc` 永远先用来退出全屏。

**录制键位时按 `Esc` / `Tab` 是取消**；关面板、切页签也会自动退出录制，不会把「关面板」那一下录成快捷键。

## 自检修复（2026-11-16，2.5.0）

一轮「按审计清单逐条修」的结果，都是能落到行为上的：

**安全 / 稳定**

- 所有写接口要求自定义头 `x-dsh-music-client: 1`：跨站网页无法用它发简单请求（自定义头会触发预检），堵掉「任意网页改设置 → 读任意文件 / 跑任意程序」那条链。
- 三处 `createReadStream().pipe()` 补 `error` 监听：文件在 stat 与打开之间被删/被搬/盘掉线时，不会再以 uncaughtException 带走整个宿主。
- Range 请求修 `end < start`：`bytes=100-50` 现在回 416，不会再出现「206 头已发 → 负 content-length → 请求永久挂着」。
- `readBody` 改成收 Buffer 再解码（中文歌单名跨 chunk 不再变成乱码），超限立刻断开并回 413，坏 JSON 回 400（不再静默当成 `{}` 且返回成功）。
- `/api/playback` 白名单收敛：布尔/枚举/数值区间/队列数组逐个校验，垃圾字段进不来。
- 遥控命令 30 秒过期 + ack 后 bump rev；客户端按命令 id 去重，ack 失败会重发，按一次「下一首」不会再跳两首。

**数据安全**

- `addTrack` 命中已有条目时保留用户维护的标签/分类/收藏/封面/播放次数（重下同一首不会把这些清回默认值）。
- `removeTrack` 改成「先删文件、后删索引」；文件被占用时抛 `file_locked`，不再出现「索引没了、文件还在 → 下次扫描复活且元数据全丢」。
- 迁移目录用目录边界比较（`E:\DshMusic` 不会把 `E:\DshMusic-备份` 一起搬），每搬 20 首落一次盘。
- 下载队列上限只淘汰已结束任务；排队超限的标 `cancelled` 并给出原因，不再静默消失。
- 启动时清理上次被强杀留下的 `.asrc/.vsrc` 临时片。

**性能**

- `has()` 从「每次线性扫全库」改成路径索引；扫描 1000 首从 O(N²) 降成 O(N)。
- `buildState()` 一次遍历建「曲目 → 歌单」映射，不再每首歌重扫歌单；`ffmpeg` 存在性缓存一分钟。
- 客户端：同 rev 且无命令时直接跳过 `setSnapshot`；失败/超时复用同一个请求（不再静默丢弃并发刷新）；排序改用共享的 `Intl.Collator`；拖滑杆/取色器 300ms 防抖，一次拖动只发一个 POST；音量写 localStorage 只在音量真的变化时；会话 store 只订阅「主视图 id」这一个字符串。

**交互 / 布局**

- 批量「删文件」需要二次确认（按钮就地变红字「确认删 N 个文件」），和旁边只摘索引的「移除」区分开。
- 曲库行支持键盘：`Tab` 能聚焦、`Enter`/`空格` 播放；`:focus-visible` 有焦点环，`:focus-within` 与触屏（`hover:none`）下操作按钮常显。
- 面板/视频窗在窗口缩放后自动夹回可视区；拖拽时若在窗口外松手会自动结束（`pointercancel` + `buttons===0`）。
- 静音会记住静音前的音量，取消静音不再一律跳回 60%。
- 提示条后到顶前到（不再被上一条的定时器提前清掉）；存储迁移的「再点一次」绑定到具体目标目录。
- 渲染兜底不再静默返回 `null`：出错时给一条带「重试」的提示。
- 新增排序项「最近播放」（按第一次播放时间倒序），点歌结果超时后会自动轮询 `/api/ask/status` 补上答案。

### 2.6.0：拖动、重渲染、死代码

- **媒体源策略**：宿主本来就按 Range 出 206（`Content-Range` / `Accept-Ranges` / 非法区间回 416，实测 96MB 文件 `bytes=50000000-50001023` 正常、`bytes=100-50` 回 416）。客户端把「整段读成 blob」的阈值从 80MB 抬到 **`settings.blobMaxMB`（默认 256）**——Chromium 的大 blob 会落盘、不再全吃内存，绝大多数 1080p 视频因此走 blob，`seekable` 直接等于全长；真超过阈值才退回 HTTP 流式，进度条旁会显示「流式 · 可能拖不准」，不再静默按旧行为跑。
- **播放位置独立 store**：`timeupdate`（约 4Hz）不再写进 `player` 状态，改走 `subscribePosition`/`usePosition`；只有进度条和时间文本两个小组件订阅它，`player.position` 每 2 秒才同步一次（供上报与恢复）。面板、曲库列表、页签不再跟着播放进度整树重渲染。
- **死代码清理**：`fmtSize`、`lastCommand`、`.mp-pop*`（含一段孤儿声明）、`.mp-video[data-full]` 死选择器、`MusicStore.reorder()`、`bili.formatDuration()`、两个文件的 `statSync` 未用导入。

## 动效

**动画只在面板或视频窗可见、且页面可见时跑**；切走窗口或全部收起时静止，`settings.json` 里能关。

## 下载管线

```
BV 号 → /x/web-interface/view（取 cid）
      → /x/player/playurl?fnval=4048
         ├─ 音频：码率最高的 DASH 音频流 → tmp → ffmpeg -vn -acodec libmp3lame -q:a 2 → *.mp3
         └─ 视频：avc1 优先的 DASH 视频流 + 音轨 → tmp → ffmpeg -c copy -map 0:v -map 1:a -movflags +faststart → *.mp4
```

- ffmpeg 就是唧唧DOWN 装的那个定制构建（`libmp3lame` + `mp3`/`mp4` muxer + `mov/flv` demuxer，够用且小）。
- 找不到 ffmpeg 时音频退化成 `.m4a`，任务里会留一句说明。
- 唧唧DOWN 的 `Download` 目录默认一起入库（「外观 → 唧唧目录」），以前手动下的文件直接就在曲库里。

| 文件 | 内容 |

## 已知边界

- 唧唧DOWN 1.240（WPF 版）没有可用的命令行下载模式：带任何参数启动都会自己退出，所以插件不调它的窗口，只复用它的 ffmpeg 与目录。
- 番剧、直播没有 DASH 流，会报「没有可用音频流 / 视频流」。
- 视频清晰度取决于账号权限：未登录一般最高 480P/720P，登录（cookie）才拿得到更高。
- 时长本地文件读不到，等第一次播放时由播放器回填。
- 支持的扩展名：音频 `.mp3 .m4a .aac .flac .wav .ogg .opus .weba`，视频 `.mp4 .mkv .flv .webm .mov .avi .ts`。
